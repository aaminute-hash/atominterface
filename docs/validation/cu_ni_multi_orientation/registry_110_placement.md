# (110)：把 (111) 的修复照搬过去会发生什么

**结论一句话：会变差 2.55 倍。** (111) 的修复是"沿衬底堆垛矢量平移"——在 (111) 上
切割把 film 留在 on-top，所以平移后落在 fcc 空位；在 (110) 上切割把 film 留在
ridge，同一句规则把它送到 **short-bridge**，γ_int 从 0.5952 涨到 1.5189。
要拿到扫描最小值 0.0881，必须是**目标式摆放**（先定位点，再算平移量），不是加增量。

本文件是为 `docs/design/registry_field.md` 提供证据，不是改变任何默认行为。

---

## 1. 为什么问这个问题

PR #30 修复了 (111) 的 on-top 缺陷，但没有碰 (110)：(110) 的 as-built 横向偏移是
1.8075 Å，远大于 `ON_TOP_LATERAL_TOL`（1e-6 Å），触发条件不满足，于是 (110) 仍然
从 ridge 出发。而归档自己把 (110) ridge 的 0.5953 J/m² 标为"对称性锁定的驻点假象"
（扫描最小值 0.088，6.8 倍）。

所以问题很自然：把同一条规则放宽到 (110) 会怎样？

## 2. 四臂实测

Cu/Ni(110)，`--min-thickness 14.4`，其余与归档厚度扫描逐项相同（vacuum 15.0、
gap 2.0、fmax 0.002、max-steps 400、max-candidates 1、dtype 默认 float32）。
源码 v0.4.1（`main` @ `5cd92751b`）。

| 臂 | 摆放方式 | 位点（面内分数） | γ_Cu | γ_Ni | **γ_int** | E_interface (eV) |
|---|---|---|---|---|---|---|
| as-built | 不动（当前行为） | ridge (½, 0) | 1.5684 | 2.1191 | **0.5952** | −115.099365 |
| +step | 无条件加衬底堆垛步 | short-bridge (0, ½) | 1.5684 | 2.1191 | **1.5189** | −114.566643 |
| target:trough | 摆到 top+堆垛步 | trough (½, ½) | 1.5684 | 2.1191 | **0.0881** | −115.391869 |
| target:on-top | 摆到 (0,0) | on-top (0, 0) | 1.5684 | 2.1191 | **2.0332** | −114.270020 |

γ 单位 J/m²，换算 1 eV/Å² = 16.0218 J/m²。表面项四臂**逐位相同**（只有界面项变），
这与 (111) 那次重测的形态一致。

## 3. 对照：归档的四位点扫描

| 位点 | 本文件 γ_int | 归档 γ_int | 本文件 E_interface | 归档 E_interface |
|---|---|---|---|---|
| ridge | 0.5952 | 0.5952 | −115.099365 | −115.099365 |
| short-bridge | 1.5189 | 1.5189 | −114.566643 | −114.566643 |
| trough (fcc-cont) | 0.0881 | 0.0881 | −115.391869 | −115.391869 |
| on-top | 2.0332 | 2.0332 | −114.270020 | −114.270020 |

**四臂的 E_interface 与归档逐位一致到六位小数。** 归档是在 `c440b81` + mace-torch
0.3.17 + pymatgen 2026.10.24 上测的，本文件在 v0.4.1 + 0.3.16 + 2026.9.24 上测，
两者一致意味着：这四个数是可复现的物理量，不是某个环境的产物。

## 4. 几何上的原因

| 取向 | as-built 偏移 | 衬底堆垛步 | "加一步"落到哪 |
|---|---|---|---|
| (111) | (0, 0)（on-top） | (⅓, ⅓) | (⅓, ⅓) = **fcc 空位** ✓ |
| (110) | (½, 0)（ridge） | (−½, −½) | (0, ½) = **short-bridge** ✗ |

(111) 上切割恰好把 film 留在衬底的**亚晶格位置**上，所以"加一步"等于"走到下一个
亚晶格"，语义正确。(110) 上切割把 film 留在**两条原子行之间的中点**（ridge），
不是亚晶格位置，加一步就落到另一个中点（short-bridge），语义全错。

**这不是 (110) 的特殊性，是"增量式"规则的前提在 (110) 上不成立。**

## 5. 一个过程中的教训（保留下来，因为它会再犯）

第一版的目标式实现把**笛卡尔差**当分数坐标回绕了。回绕一个笛卡尔差没有意义
（晶格不是立方的），而它**不报错**：film 被摆到偏离请求位点约 0.31 个晶格常数的
地方，松弛时从那里滑走，on-top 那一臂给出了 γ_int 0.090 —— 一个和请求位点无关的
数，而且看起来完全正常。

正确的换算顺序是"先取分数坐标 → 回绕 → 再乘回笛卡尔"。改完后 on-top 给 2.0332，
与归档逐位一致。

**判据**：不要只看能量像不像，**要实测落点**。摆放错了能量也可能落在某个极小上。

## 6. 复现

```bash
# 四臂；run_110.py / run_110_target.py 只替换 coh._off_on_top_shift，不改 src
python -u run_110.py asbuilt  out/110_asbuilt 14.4      # 当前行为
python -u run_110.py forced   out/110_forced  14.4      # 无条件加堆垛步
python -u run_110_target.py trough  out/110_trough 14.4 # 目标式：top+堆垛步
python -u run_110_target.py on_top  out/110_ontop  14.4 # 目标式：(0,0)
```

位点判定：读 `01_interface_relaxed.extxyz`，取 Cu 顶层与 Ni join 层，把面内差矢量
换算成分数坐标（**先乘 `inv(sub_2d)`**）后回绕，与请求值比对。

## 7. 本文件不改变任何默认行为

v0.4.1 的 (110) 仍然从 ridge 出发、仍然给 0.5952、仍然告警。改不改默认值、以及
改成什么，见 `docs/design/registry_field.md` §9 —— 那是需要拍板的决定，不是本文件
能替你做的。
