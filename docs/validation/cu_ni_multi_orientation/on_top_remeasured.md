# (111)@14.4 Å 的 on-top 值：修复后重测

`metadata.yaml` 的 `superseded` 块此前标的是 `remeasured_after_fix: false`——
意思是"这个数不再由当前代码产生，但我们没有新值"。本文件补上那个新值。

**结论：0.8981 → 0.0812 J/m²。修复后该厚度的 γ_int 与 18.0 档在同一个环境里
给出同一个数，厚度伪影消失。**

---

## 1. 为什么不能只跑一遍就报数

在当前 `main` 上直接跑 14.4 档，得到 0.0812。但"新值"与"归档值"来自**不同
环境**：

| | 归档（`c440b81`） | 本次重测 |
|---|---|---|
| mace-torch | 0.3.17 | **0.3.16** |
| pymatgen | 2026.10.24 | **2026.9.24** |
| atominterface | `c440b81` | `main` @ `e01476491`（含 PR #30） |

两个变量同时变了（代码变了，环境也变了），差值无法归因。所以本记录用
**同环境 A/B**：同一份源码、同一进程、同一协议，只把
`_off_on_top_shift` 换成长度为零的版本——那就是修复前的行为。两臂之差
因此只能来自这一个位移。

## 2. 方法

- **源码**：`main` @ `e01476491`（含 PR #30 的 `1a305c3`）。
- **入口**：`examples/03_interface_energy.py`，参数与归档厚度扫描逐项相同：
  `--vacuum 15.0 --max-candidates 1 --fmax 0.002 --max-steps 400`，
  `dtype` 取默认 `float32`（与归档一致），`--gap` 取默认 2.0。
- **A 臂（pre-fix）**：
  ```python
  import numpy as np
  import atominterface.builders.coherent as coh
  coh._off_on_top_shift = lambda *a, **k: np.zeros(2)
  ```
  只替换这一个函数。`_assemble_interface` 的其余步骤、参考态
  （`strained-coherent`）、能量定义全都不变。
- **B 臂（post-fix）**：不改任何东西。
- 两臂各跑 14.4 与 18.0 两档，共四次；另加一次 14.4 档的 fmax 对照（§6）。

## 4. 怎么读这张表

**① 18.0 两臂逐位相同。** `E_interface` 到 6 位小数一致（−87.046448），
γ_int 同为 0.0812。PR #30 的位移只在 `n_Cu ≡ 1 (mod 3)` 的族上触发，
18.0 档有 9 个 Cu 层（9 mod 3 = 0），不触发。**修复在非 on-top 族上是严格
恒等**，没有附带改动。

**② 14.4 只变界面项。** 表面项（0.081101 / 0.113825 eV/Å²）、体相参考、
两侧 slab 能量两臂完全相同；唯一变化的是 `E_interface`：
−72.875717 → −73.164230，Δ = **−0.288513 eV**。所以差值全部落在界面键合项
上，不是参考态漂移。

**③ 换算闭合。**
0.288513 eV ÷ 5.658707 Å² × 16.0218 = **0.8169 J/m²**，
而 0.8981 − 0.0812 = 0.8169 J/m²。残差在 1×10⁻⁴ 以内，来自 4 位小数的显示截断。

**④ 归档值被复现，环境差可忽略。** A 臂给出 0.8981。归档对这个配置有两处
记录，分别是 **0.8981**（`registry_vs_thickness.csv`）与 **0.8980**
（`registry_scan.csv`）——同一个数的末位，来源不同，见 `derived_columns` 里对
该文件末位差异的说明。表面项两臂都是 **1.2994 / 1.8237**，与归档的
1.2994 / 1.8237 **逐位相同**。mace-torch 差一个次版本、pymatgen 差一个月份
版本，没有改变任何一个被讨论的量，所以 B 臂的 0.0812 可以直接与归档的其它档
比较。

## 5. 位点的独立确认

数值之外，位置也要对得上，否则"0.0812 与 18.0 相同"可能只是巧合。

修复后 film 的 join 层落在面内分数坐标 **(+1/3, +1/3)**，横向偏移
**1.4758 Å**，即共格胞的近邻距离 2.556 Å 除以 √3，**与理想位偏差 0.0000 Å**。
紧邻下方那一层（次顶层）在该位置**没有原子**——正下方最近的 Cu 在两层以下，
所以是 **fcc 空位**，不是 hcp 空位。

这与归档 `registry_scan.csv` 中 18.0 档 `fcc-hollow` 行的
`offset_u = +0.3333, offset_v = +0.3333` 是同一个位点。

**位置**（本文件的几何判定）与**数值**（归档那 4 个位点的显式扫描最小值）
是两条独立证据，二者一致。

## 6. 顺带补上的 fmax 对照

归档 `reproduce.md` §1.5 里有一句"**(111) 的 14.4 Å 档不做 fmax 对照**——它被
on-top 锁死，fmax 效应会被 11 倍的注册误差淹没"。理由是真的，但现在这个理由
**没有了**：14.4 不再落在 on-top，可以做了。

| `--fmax` | γ_int (J/m²) | 说明 |
|---|---|---|
| 0.002 | 0.0812 | 归档约定的收敛值 |
| 0.01 | 0.0817 | 默认批次 |

差 = γ(0.01) − γ(0.002) = **+0.0005 J/m²**，方向与全项目约定一致。
量级上：比 (001) A 簇的 +0.0050 小一个数量级，比这次修掉的 0.817 小三个
数量级。**fmax 从来不是这个厚度上的问题**，把它当问题的是注册。
14.4 档因此不必再在协议里单列例外。

## 7. 一条必须说清的限定

两臂的 film 在松弛过程中**面内都没有移动**：横向偏移在松弛前后都等于初态值，
面内离散 0.0000 Å。

这不是"松弛把它推到了正确位置"。空位本身也是 3 重对称点，面内梯度同样为零，
松弛同样不会横向移动它。**修复生效的原因是初始摆放换了，不是搜索能力变了。**

这正好解释了为什么 `registry` 字段仍然缺失：用户依然不能**请求**位点。
builder 只是不再必然落在错误的那一个上——它落在衬底堆垛序列给出的那个上，
而那个恰好是物理上正确的空位。

## 8. 复现

```bash
# 两臂各跑两档，只差一行 monkeypatch
cd <worktree> && PYTHONPATH=<worktree>/src python -u run_ab.py prefix  out/prefix_14 14.4
cd <worktree> && PYTHONPATH=<worktree>/src python -u run_ab.py shipped out/shipped_14 14.4
# 第三、四个参数是厚度与 fmax，默认 14.4 / 0.002
```

`run_ab.py` 的全部内容就是：`importlib` 加载 `examples/03_interface_energy.py`，
A 臂替换 `coh._off_on_top_shift`，然后用同一组 argv 调用 `main()`。没有改动
`src` 下任何文件。

位点判定另用一个独立脚本读 `01_interface_relaxed.extxyz`，取 Cu 顶层与 Ni
join 层，把面内差矢量换算成分数坐标并与 (0,0) / (1/3,1/3) / (2/3,2/3) 比较；
hcp 还是 fcc 由**紧邻下方那一层在该位置有无原子**决定。
